\section{Diagnostic and revision prompts}
\label{app:prompts}

The diagnostic and revision prompts connect policy semantics to numerical execution evidence.
The LLM first proposes analyses using the code and schema, then receives their results as the basis for a possible edit.

\subsection{Hypothesis generation and analysis execution}
\label{app:diagnostic-prompts}

The system prompt asks the LLM to consider nominal behavior and possible anomalies before writing analysis code.
It requests explicit hypotheses, defensive functions over a dataframe, and output in a common results file.
The full numerical rollout is an input to these generated functions rather than part of the initial diagnostic-generation context.
\VerbatimInput[breaklines=true,breakanywhere=true,fontsize=\footnotesize]{appendices/prompts/diagnostics_system.txt}

The per-policy template supplies the environment description, model definition, and available columns.
\VerbatimInput[breaklines=true,breakanywhere=true,fontsize=\footnotesize]{appendices/prompts/diagnostics_input.txt}

\subsection{Revision, additional tests, and termination}
\label{app:revision-prompts}

The revision prompt offers three responses: provide an updated program, request more diagnostic tests, or indicate that no further action is needed.
It allows changes to the computations and parameterization while preserving the model interface and logging outputs.
Algorithm~\ref{alg:refinement} summarizes the data flow and permitted interaction branches.
Here $\Sigma(C)$ denotes the table-column schema exposed by the environment and the policy's logging interface.
Analysis-code generation depends on this schema and the policy program, independently of the numerical rollout values.

\begin{algorithm}[htbp]
\caption{Refinement through semantic rollout analysis}
\label{alg:refinement}
\begin{algorithmic}[1]
\REQUIRE Task specification $S$, demonstrations $\mathcal D$, environment
\STATE $C\gets\mathrm{LLM}(S,\text{generation specification})$
\WHILE{the refinement procedure continues}
    \STATE $\theta\gets\mathrm{Fit}(C,\mathcal D)$; $\hat\pi\gets\pi_{C,\theta}$
    \STATE $T\gets\mathrm{LLM}(S,C,\Sigma(C),\text{diagnostic prompt})$
    \STATE $X\gets\mathrm{RolloutLog}(C,\theta)$
    \REPEAT
        \STATE $r\gets\mathrm{Execute}(T,X)$
        \STATE $b\gets\mathrm{LLM}(S,C,T,r,\text{revision context})$
        \IF{$b$ requests additional diagnostics}
            \STATE $T\gets$ additional analysis code
        \ENDIF
    \UNTIL{$b$ proposes a revised program or stops refinement}
    \IF{$b$ stops refinement} \STATE \textbf{break} \ENDIF
    \STATE $C\gets$ revised program from $b$
\ENDWHILE
\STATE \textbf{return} $\hat\pi$; optionally apply post-refinement RL
\end{algorithmic}
\end{algorithm}

\VerbatimInput[breaklines=true,breakanywhere=true,fontsize=\footnotesize]{appendices/prompts/revision.txt}

The refinement loop has a configurable iteration budget, with a default maximum of six rounds and early termination through the LLM's stop response.
Additional tests run on the current table before the next revision decision.
If fitting a revised program fails, the LLM can regenerate it using the preceding policy and diagnostic context, with up to five attempts.

\section{Training and evaluation details}
\label{app:training}

\subsection{Imitation learning and refinement configuration}
\label{app:il}

We minimize Gaussian negative log likelihood with Adam and initialize each revised model from the coefficients specified in its generated code.
The optimizer defaults to a learning rate of 0.03, batch size 512, and 1,000 minibatch updates.
The LLM is GPT-5-mini with high reasoning effort.

Each task uses one demonstration, with evaluation over ten unseen settings.
Car Racing evaluation uses mean actions, a maximum horizon of 1,000 steps, and environment seeds 1000--1009.
Door Opening evaluation samples Gaussian actions over 500-step episodes, with environment and PyTorch sampling seeds 0--9 (Appendix~\ref{app:door-record}).
For these evaluations, uncertainty is the population standard deviation across episodes.

\subsection{Post-refinement reinforcement learning}
\label{app:rl}

We optimize a clipped policy-gradient objective using group-relative reward-to-go and window likelihoods.
For trajectory $i$, let $T_i$ be its length and let $\mathcal I_t$ contain trajectories valid at time $t$.
We compute
\begin{equation}
 R_t^i=\sum_{u=t}^{T_i-1}\gamma^{u-t}r_u^i,
 \qquad A_t^i=\frac{R_t^i-\mu_t}{\sigma_t+10^{-8}},
 \label{eq:rl-advantage}
\end{equation}
where $\mu_t$ and $\sigma_t$ are the population mean and standard deviation over $\mathcal I_t$.

The likelihood ratio multiplies action likelihoods over a window of $L$ valid steps.
In log-probability form,
\begin{equation}
 \rho_{it}(\theta)=\exp\!\left[
 \sum_{u=t}^{t+L-1}\bigl(\log\pi_\theta(a_u^i\mid s_u^i)
 -\log\pi_{\theta_{\mathrm{old}}}(a_u^i\mid s_u^i)\bigr)\right].
 \label{eq:rl-ratio}
\end{equation}
For valid window starts, the clipped objective is
\begin{equation}
 \mathcal J(\theta)=\mathbb E_{i,t}\!\left[
 \min\!\left(\rho_{it}(\theta)A_t^i,
 \operatorname{clip}(\rho_{it}(\theta),1-\epsilon,1+\epsilon)A_t^i\right)\right].
 \label{eq:rl-objective}
\end{equation}
An entropy bonus encourages exploration, with its coefficient decaying linearly over training.
The optimizer defaults are $\gamma=0.98$, clipping threshold $\epsilon=0.2$, Adam learning rate $0.007$, 20 sampled episodes per update, three optimization epochs, and initial entropy coefficient 0.01; the default Car Racing likelihood window is 150 steps.
Unlike GSPO's length-normalized sequence ratio~\citep{zheng2025group}, Eq.~\eqref{eq:rl-ratio} uses the product of likelihoods within each window.
Trajectories share an initial condition and are grouped by time step for advantage estimation.

\subsection{Statistical comparisons}
\label{app:statistics}

Table~\ref{tab:statistics} reports the six two-sided comparisons in Section~\ref{sec:refinement-results}, with Holm correction controlling the family-wise error rate across these tests.
For Car Racing, we estimate Welch statistics from Table~\ref{tab:results}, taking $n=10$ per policy and converting each population standard deviation $\sigma$ to the sample variance $s^2=n\sigma^2/(n-1)$.
The standard error is $\sqrt{s_A^2/n+s_B^2/n}$, with Welch--Satterthwaite degrees of freedom.
These are independent-sample approximations; the shared evaluation settings call for paired comparisons, whose cross-policy covariance cannot be determined from aggregate summaries.
The estimates therefore describe evidence under this independence assumption, rather than exact paired significance.

Door Opening compares episode-minimum distances for iterations 0 and 3, paired by the same initial handle position, target, and action-sampling seed.
The mean distance reduction is 0.4375, with a paired 95\% confidence interval of $[0.3926,0.4823]$ and $t(9)=22.07$.
All tests characterize variation across evaluation episodes for the fitted policies, not variation across independent training or refinement runs.
No significance test is applied to MLES.

\paragraph{Observation timing.}
The recorder evaluates the model, advances the environment, and then writes the observation columns.
Consequently, each row contains current-step latents but successor-step observations.
Several generated observation-consistency checks compare values across this one-step offset, producing false inconsistency flags.
The target-speed reconstruction and the plotted latent trajectories use quantities from the same forward pass.

\paragraph{Sensor meanings.}
The environment normalizes vehicle speed by 100 and wheel angular readings by 200.
Their difference defines a normalized slip proxy in the recorded policies, rather than a physical slip velocity.
The policy-generation prompt labels the second indicator as absolute heading; the environment supplies a wheel-joint steering angle in this field.

\subsection{Door Opening progression}
\label{app:door-record}

The Door Opening policy develops a coordinated reach-and-pull strategy over three revisions.
The initial policy approaches ineffectively, while intermediate revisions alter the approach before the third revision coordinates it with pulling.
We evaluate the fitted policy after each revision using sampled Gaussian actions across ten distinct handle and target configurations, with a 500-step horizon.
The evaluation environment uses Meta-World 3.0.0, MuJoCo 3.3.7, Gymnasium 1.1.1, and PyTorch 2.5.1.

For episode $e$, the metric is
\begin{equation}
 d_e^{\min}=\min_{1\le t\le T_e}
 \bigl\|h_{e,t}-g_e\bigr\|_2,
 \label{eq:door-distance}
\end{equation}
where $h_{e,t}$ is the world-space position of the simulator's handle geometry after a step, $g_e$ is its target position, and $T_e\le500$.
We report the mean and population standard deviation of $d_e^{\min}$ across the ten episodes.
The sequence is $0.547530\pm0.000000$, $0.544925\pm0.007813$, $0.539759\pm0.022594$, and $0.110052\pm0.059459$, corresponding to the four policies in Figure~\ref{fig:door_iterations}.
