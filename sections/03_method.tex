    \item Explain initial code and parameter initialization from the task

    \item \textbf{Running example continuation:} refer to the policy topology

    \item Explain how training and initialization work after an edit; recover

    \item \textbf{Running example, textual explanation only:} describe the

\subsection{Recording semantic execution traces}
\label{sec:traces}
\begin{itemize}
    \item Explain how executing the fitted policy produces a table with time
    steps as rows and observations, parameters, intermediate values, and actions
    as columns. Policy parameters remain fixed within an evaluation rollout.
    Emphasize that the structure exposes latent computations as well as external
    observations and actions, allowing their evolution to be tracked.
    \item Describe the generated model's \texttt{info\_dict}, semantic key names,

    \item Distinguish predicted action-distribution quantities from sampled or
    clipped executed actions. Full numerical logs go to external analysis code;

    \item \textbf{Running example, panel B---latent traces:} align a few plots

\subsection{Generating and executing diagnostics}
\label{sec:diagnostics}
\begin{itemize}
    \item List the LLM inputs: task description, current policy code, and table
    column names. Explain the prompt's progression from expected behaviors and
    possible anomalies to hypotheses and executable analysis functions.
    \item Show a short generated test and its numerical output. Cover the role
    of sign/range checks, reconstruction checks, correlations, and behavioral
    statistics without reproducing the full diagnostic taxonomy here.
    \item Explain external execution on the complete table and return of
    diagnostic summaries to the LLM. These analyses supply evidence for proposed
    edits; they do not certify the underlying semantic assumptions.
    \item \textbf{Running example, panel C:} use the source's steering-alignment
    diagnostic as a candidate: the fraction of steps with
    $\mathrm{steer}\cdot\mathrm{closest\_x}>0$, including an off-track subset.
    Verify the sign convention and show the actual output from the selected
    run. Explain that lateral correction alone is not a complete specification
    of steering during a turn; the statistic requires task context.
    \item Explain the analogy's scope: some checks resemble numerical
    assertions, while others summarize temporal or statistical behavior.
    Continuous, correlated, potentially stochastic rollouts need not yield a
    single binary pass/fail result. Call these diagnostic checks rather than
    imply conventional unit tests with a known correct output.
\end{itemize}

\subsection{Revising the program and continuing the loop}
\label{sec:revision}
\begin{itemize}
    \item Specify the revision context: current program, generated tests,
    diagnostic results, and task information. Explain how the LLM relates an
    observed issue to a proposed change in a computation or constraint.
    \item Describe the prompt's three branches: propose a revised program,
    request additional diagnostics, or declare no further changes needed.
    Distinguish these available branches from the sequence actually used in
    the experiments; document budgets and stopping criteria from records.
    \item Describe retraining, fresh execution, and regeneration of the table
    schema/tests when the program changes. Record initialization and distribution
    edits separately from topology changes. Do not invent acceptance/reversion
    rules or claim convergence or monotonic improvement.
    \item \textbf{Running example, panel D:} show the selected run's actual
    before/after computation and the diagnostic rationale, then the refitted
    policy's subsequent behavior. This closes the example within the method
    rather than postponing its explanation to the experiments.
    \item Clarify the rerun analogy: changed structure must be trained again
    before execution is informative. Tests can change with the program; do not
    imply a fixed regression suite or a mandatory test-passing acceptance gate
    unless it existed in the reported implementation.
    \item \textbf{Missing evidence for panels A--D:} recover matched programs,
    fitting context, logs, diagnostics, edit, and evaluation. Do not connect the
    displayed steering test to unrelated slip-weight outputs or constraints.
    If unavailable, label the example schematic and separate it from measured
    empirical evidence.
\end{itemize}
