\section{Introduction}
\label{sec:introduction}

Learning a control policy from a small number of demonstrations depends on choosing a useful policy structure.
A driving demonstration, for example, contains steering and pedal commands, but does not explicitly state how track geometry, target speed, and lateral correction should interact.
Knowledge Informed Models (KIM) address this problem by translating an expert's strategy description into a structured policy and fitting its numerical parameters to demonstrations~\citep{zhu2025sample}.
The policy computes actions through named latent quantities, such as target speed and speed error, that express the expert's intended strategy.

An LLM can reduce the burden of writing that strategy, but its initial structure may not match the relationships needed to reproduce the demonstration reliably.
A model may label a wheel-speed reading as ``slip,'' for example, even though wheel speed also increases during ordinary forward motion.
Gradient training can compensate by changing coefficients, including reversing a coefficient's intended sign, but it cannot replace the feature computation or add a missing dependency on vehicle speed.
The problem is therefore not just how to fit the initial policy, but how to revise the assumptions encoded in its program.

We approach structural refinement as code debugging.
When a program behaves unexpectedly, a coding agent can inspect intermediate values, write checks, run them, and use their outputs to revise the code.
We apply the same pattern to a trainable controller: fit it to a demonstration, execute it in the environment, investigate its internal behavior, and edit the policy before training again.

A structural edit becomes a hypothesis tested through another round of learning and execution.

Semantic structure makes this debugging interface concrete.
An aggregate return indicates how well the car drove, whereas a named latent such as target speed identifies a computation whose inputs and outputs can be examined.
Logging those quantities creates a table with interpretable columns and one row per execution step.
Given the program and column names, an LLM can generate analyses of coefficient signs, speed regulation, or action saturation, then connect the results to specific computations that it can change.
The numerical analyses run outside the LLM on the complete table, so the model reasons over diagnostic results instead of reading thousands of trajectory rows.

Our method alternates these two forms of learning: gradients fit the parameters within a structure, while execution analysis guides revisions to the structure itself.
The initial LLM uses the task description and observation semantics; the numerical learner uses the demonstration.
The resulting controller runs independently of the LLM at deployment.
Our contributions are:
\begin{itemize}
    \item An iterative refinement procedure that combines demonstration-based parameter fitting with LLM-guided revision of a structured policy program.
    \item A tabular data-analysis interface grounded in the policy's semantic latents, using generated executable checks to connect rollout evidence to program edits.
    \item Experiments on Car Racing and Door Opening showing improved imitation learning, generalization to unseen settings, and more efficient subsequent reinforcement learning, together with analyses of feedback and structural changes.
\end{itemize}
Building on KIM's structured-policy representation, our method uses its exposed semantics to refine the LLM's initial control strategy through execution.
