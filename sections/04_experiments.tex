\section{Experiments and analysis}
\label{sec:experiments}

We evaluate iterative refinement on Car Racing and Door Opening using one demonstration per task.
The experiments test whether iteration improves policies, compare the complete pipeline with gradient learning and program evolution, and examine how semantic analysis guides refinement.

\subsection{Environment setup and choice of baselines}
\label{sec:setup}

We choose two tasks with complementary challenges: Car Racing tests long-horizon behavior where small errors accumulate, while Door Opening requires distinct approach and pull stages with abrupt changes in appropriate actions at contact.
Both tasks use continuous actions and low-dimensional semantic observations ( detailes in Appendix~\ref{app:environment}).
A human using a joystick provides the Car Racing demonstration, and a motion planner provides the Door Opening demonstration.

% Its return rewards track coverage with a per-step penalty.
% Door Opening uses Meta-World~\citep{mclean2025metaworld} and supplies current and previous gripper/door information and a target position; actions control Cartesian gripper motion and opening or closing.
% The task requires approaching the handle and then pulling.
% We report the minimum Euclidean distance from the simulated handle to its target over a 500-step episode, averaged across ten episodes; smaller values indicate greater progress.
% Door Opening actions are sampled from the learned Gaussian policy.

% Policies are evaluated in ten unseen settings, including different Car Racing layouts and unseen configurations of the Door Opening task.

\paragraph{Iteration improves performance}

Table~\ref{tab:results} shows that structural refinement improves performance over the zero-shot structure with no refinement.
Under imitation learning, the refined policy significantly outperforms the zero-shot model by $15\%$ ($p \approx 0.007$), with performance similar to human demonstrations.
This verifies our hypothesis that refinement corrects the mismatch between the LLM's pretrained task knowledge and the demonstration's true structure.

The zero-shot structure requires significantly more RL steps for similar performance ($2000$ vs $404$ resets), showing that a better structure improves RL efficiency.
The zero-shot structure is expected to eventually match performance because it is \textit{inconsistent} with the expert demonstrations, rather than inherently \textit{wrong}.
This also explains why low-budget RL underperforms IL ($p \approx 0.010$): the policy must \textit{unlearn} IL parameters at a local optimum.

This also holds for Door Opening, where structural refinement produces a reach-and-pull policy that generalizes from one demonstration to unseen configurations (Figure~\ref{fig:door_iterations}).
The initial policy's linear-motion assumption causes upward drift; the next revision adds an arc toward the handle but no pull, before later refinement learns both approach and pull.
Refinement reduces the minimum handle-to-target distance by approximately 80\% ($p<10^{-4}$).

\paragraph{Performance comparison wih other baselines}
The refined structure outperforms the MLP in mean return under each matched learning condition.
After IL, it achieves $38\%$ better performance than MLP ($p\approx0.019$); at the low RL budget, it also achieved $52\%$ better ($p\approx0.021$).
At the high RL budget, the refined policy has Table~\ref{tab:results}'s highest mean return (906.5 vs 850.2 for MLP), but the difference is not statistically significant ($p\approx0.136$).

Combining structural refinement with gradient learning also achieves high returns with far fewer LLM queries than program evolution alone.
With 16 queries, MLES reaches 240.0 return, compared with 900.5 for the refined policy with a single demonstration.
MLES reaches similar performance at 847.1 with 2,016 queries, $224x$ the refined policy's query count, and 8,064 environment resets.
It therefore requires a much larger search budget to approach the performance of the refined pipeline.

These comparisons show that combining symbolic structure with continuous updates from demonstrations is more efficient than either component alone.

\subsection{Ablation on feedback type}
\label{sec:feedback-results}

Execution feedback improves both the quality and trajectory of policy refinement (Figure~\ref{fig:result-car}).
We compare generated analysis with two conditions: 1) direct trajectory-table feedback, providing the entire rollout table to the LLM, and 2) revision without execution feedback.
Without closed-loop environment feedback, asking the LLM to improve the structure increases misalignment and causes return to collapse.
Both feedback conditions reach high returns, but direct table feedback is more unstable, dropping to 415.4 at the second revision.
The analysis-based condition remains above 839 across all four revisions, providing more consistent improvement along this refinement trajectory.

Our data analysis method uses only $25\%$ of the input tokens required by table feedback (Table~\ref{tab:tokens}).
Output usage doubles because the LLM generates analysis in addition to structure code, but the total number of processed tokens remains much lower.
